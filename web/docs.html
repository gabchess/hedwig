Install Hedwig yourself

Install the local v0.4.2 MCP server by hand. Hedwig never signs or sends.

Install

You need Git, Node.js 22 or newer, and Yarn. First confirm the full commit on the v0.4.2 release on GitHub. Stop if it differs.

mkdir hedwig && cd ./hedwig && git init &&
git fetch --depth 1 https://github.com/gabchess/hedwig.git e85049bc7087f434fd732bb02e0e87ca57acd82c &&
git checkout FETCH_HEAD &&
test "$(git rev-parse HEAD)" = e85049bc7087f434fd732bb02e0e87ca57acd82c &&
yarn install --frozen-lockfile --ignore-scripts && npm ci --ignore-scripts --prefix mcp && yarn consult:build && yarn mcp:build

Fix any error before you go on.

Add it to your MCP client as a stdio server. Use absolute paths:

{
  "mcpServers": {
    "hedwig": {
      "command": "node",
      "args": ["/path/to/hedwig/mcp/dist/server.js"],
      "env": { "HEDWIG_POLICY_FILE": "/path/to/policy.json" }
    }
  }
}

Your policy

A JSON file you write and keep outside the repo:

{
  "permits": true,
  "chainId": "eip155:1",
  "approvedRecipients": ["0x00000000000000000000000000000000a11ce001"],
  "perActionCaps": { "pay": "1000000" },
  "role": { "mode": "not-required" },
  "authorizationWindow": { "mode": "not-required" }
}

Set your chain, recipients and caps. Swap policies also set slippage, deadline and your addresses.

Hedwig pins the file when the server starts. Changed bytes return UNKNOWN with ADAPTER_POLICY_CHANGED, and a restart pins the new contents. Keep the file where your agent cannot write it.

What your agent sends

One argument, request, holding the payment it is about to sign. This sample sends no funds:

{
  "request": {
    "action": {
      "type": "pay",
      "chainId": "eip155:1",
      "recipient": "0x00000000000000000000000000000000a11ce001",
      "asset": {
        "symbol": "USDC",
        "contractAddress": "0xA0b86991c6218b36c1d19D4a2e9Eb0cE3606eB48"
      },
      "amount": "1000000",
      "target": "0xA0b86991c6218b36c1d19D4a2e9Eb0cE3606eB48"
    }
  }
}

The server reads your policy and the current time itself.

What comes back

  • proceed: true only when every check passed and your policy permits. Your agent acts on this field.
  • verdict: ALLOW_UNDER_POLICY, DENY or UNKNOWN.
  • results: one row per check, worst first, each with a reason code and evidence.
  • support and band: how strong the proof was. They never change the verdict.

On DENY or UNKNOWN, your agent stops and tells you why.
